# `of(undefined)`, `of()`, `of(void 0)` и `EMPTY` — четири начина да върнеш "нищо"

Въпросът, който поражда тази бележка, е привидно тривиален, но заслужава внимание именно защото четирите варианта изглеждат взаимозаменяеми, а на практика се различават по едно фундаментално нещо: дали `next()` изобщо бива извикан, преди потокът да завърши.

`of(undefined)` излъчва точно една стойност — самото `undefined` — и веднага след това извиква `complete()`. Типът на резултата е `Observable<undefined>`, а не `Observable<never>`, защото `undefined` тук е реална, макар и празна на пръв поглед, стойност, преминаваща през `next()`:

```typescript
of(undefined).subscribe({
  next: (v) => console.log('next:', v),   // next: undefined
  complete: () => console.log('done'),    // done
});
```

`of(void 0)` е поведенчески идентично на `of(undefined)`, защото `void 0` е просто друг начин да напишеш `undefined` в JavaScript — двата израза са строго равни (`void 0 === undefined` връща `true`). Разликата е чисто стилистична: някои екипи предпочитат `void 0`, за да избегнат буквалното изписване на `undefined` в кода, но откъм поведение на потока няма никаква разлика спрямо предходния случай.

`of()`, извикан без нито един аргумент, е различен случай, а не просто "същото, но по-кратко". Той не излъчва нищо — `next()` изобщо не се извиква — и директно преминава към `complete()`. Типът на резултата е `Observable<never>`, защото потокът формално никога няма да носи стойност от какъвто и да е тип:

```typescript
of().subscribe({
  next: (v) => console.log('next:', v),   // никога не се извиква
  complete: () => console.log('done'),    // done
});
```

`EMPTY` е constant, не функция за извикване, и се държи идентично на `of()` откъм резултат — completes веднага, без нито едно `next()` — но семантично комуникира различно намерение. Докато `of()` без аргументи изглежда като пропуск или недовършен код, `EMPTY` е изричен, самодокументиращ сигнал: "тук нарочно няма какво да се върне, но операцията трябва да завърши валидно" — типично в клон на `switchMap`, където дадено условие не изисква реална заявка, но веригата все пак очаква observable.

```typescript
EMPTY.subscribe({
  next: (v) => console.log('next:', v),   // никога не се извиква
  complete: () => console.log('done'),    // done
});
```

## Бърза справка

| Израз           | Излъчва стойност? | `next()` извикан? | `complete()` извикан? | Типична употреба                                       |
| --------------- | :---------------: | :---------------: | :-------------------: | ------------------------------------------------------ |
| `of(undefined)` |   ✅ `undefined`   |         ✅         |           ✅           | Искаш `undefined` като смислена, реална стойност       |
| `of(void 0)`    |   ✅ `undefined`   |         ✅         |           ✅           | Идентично на горното, стилистичен вариант              |
| `of()`          |         ❌         |         ❌         |           ✅           | Рядко; технически валидно, но неясно намерение         |
| `EMPTY`         |         ❌         |         ❌         |           ✅           | Изричен сигнал "нищо за връщане" в switchMap и подобни |
