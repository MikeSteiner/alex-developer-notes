# Angular: Директиви и pipes

## Компонент, директива и pipe

Трите строителни блока на темплейта се различават по това какво правят с елемента.

**Компонентът** е директива **с темплейт**. Той създава собствено view вътре в host елемента си. На един елемент може да има само един компонент.

**Директивата** е поведение **без темплейт**, закачено към съществуващ елемент. Тя променя външния вид, поведението или структурата на елемента, но не рендерира собствено съдържание. На един елемент може да има много директиви.

**Pipe-ът** не е закачен към елемент изобщо. Той е функция, която трансформира стойност вътре в израз на темплейта.

Образът е къщата на Румяна. Компонентът е цяла стая с мебелите си. Директивата е нещо, което се добавя към вече съществуваща стая: осветление, аларма, табелка на вратата. Pipe-ът е преводачът, който превежда надписа на прозорчето на езика на минувача, без да пипа самата стая.

## Attribute директиви

Attribute директивата променя външния вид или поведението на елемента, към който е закачена. Селекторът е атрибут в квадратни скоби.

```typescript
@Directive({
  selector: '[appAutofocus]',
})
export class Autofocus {
  private readonly host = inject<ElementRef<HTMLElement>>(ElementRef);

  constructor() {
    afterNextRender(() => this.host.nativeElement.focus());
  }
}
```

```html
<input appAutofocus formControlName="email" />
```

Директивата има достъп до host елемента чрез `ElementRef`. Тя може да има inputs и outputs, както е описано в [[angular-inputs-outputs-model]]. Може да слуша събития и да задава bindings на host елемента чрез свойството `host`, описано в [[angular-content-projection-queries]].

Ако input-ът има **същото име като селектора**, един binding прилага директивата и подава стойност едновременно: `<p [appHighlight]="color">`.

Достъпът до DOM трябва да е в `afterNextRender`, а не директно в конструктора, както е в примера. Така кодът не се изпълнява при SSR, където `focus()` и другите DOM API-та не съществуват. Това е по правилото от [[angular-component-lifecycle]] и не е от страницата за attribute директиви.

## Структурни директиви

Структурната директива променя **структурата** на DOM: решава дали и колко пъти да се рендерира дадено съдържание.

### Звездичката е синтактична захар

Това е класическият въпрос. `*` пред директива е съкратен запис за обвиване на елемента в `<ng-template>`. Директивата и нейните bindings се преместват върху `<ng-template>`, а самият елемент става съдържанието на шаблона.

```html
<p *appIfRole="'admin'">Админ панел</p>

<!-- се превръща в -->
<ng-template [appIfRole]="'admin'">
  <p>Админ панел</p>
</ng-template>
```

`<ng-template>` сам по себе си не рендерира нищо. Той е описание на съдържание, което може да бъде рендерирано по-късно. Решението дали и колко пъти да се рендерира принадлежи на директивата.

От същото правило следва, че на един елемент може да има **само една** структурна директива, защото има само един `<ng-template>`, в който да се обвие. За две директиви едната се поставя на `<ng-container>`, който не добавя елемент в DOM.

### Как работи отвътре

Структурната директива получава две неща чрез DI. `TemplateRef` е референция към съдържанието на `<ng-template>`. `ViewContainerRef` е мястото в DOM, където то може да бъде рендерирано.

```typescript
@Directive({
  selector: '[appIfRole]',
})
export class IfRole {
  private readonly templateRef = inject(TemplateRef);
  private readonly viewContainer = inject(ViewContainerRef);
  private readonly auth = inject(AuthService);

  readonly appIfRole = input.required<string>();

  constructor() {
    effect(() => {
      this.viewContainer.clear();

      if (this.auth.hasRole(this.appIfRole())) {
        this.viewContainer.createEmbeddedView(this.templateRef);
      }
    });
  }
}
```

`createEmbeddedView` рендерира шаблона, а `clear` премахва всичко рендерирано. С втори аргумент се подава контекст. Свойството `$implicit` в него е стойността, която получава `let data` в темплейта.

Документацията описва и **template guards** за по-добра проверка на типовете. Статичният метод `ngTemplateContextGuard` типизира контекста. `ngTemplateGuard_<input>` стеснява типа на input-а вътре в шаблона, по същия принцип като в [[typescript-narrowing]]. Те нямат ефект по време на изпълнение.

### Кога собствена структурна директива

За обикновени условия и цикли правилният избор е вграденият control flow от [[angular-control-flow]]: `@if`, `@for` и `@switch`. Собствена структурна директива има смисъл за **преизползваема логика на рендериране**, която control flow не покрива. Примерът по-горе с проверка на роля е типичен: вместо `@if (auth.hasRole('admin'))` с инжектиране на `AuthService` във всеки компонент, правилото живее на едно място.

## Композиция с `hostDirectives`

`hostDirectives` прилага директиви към host елемента на компонент или директива **от вътре в класа**, без потребителят да ги пише в темплейта. Това е композиция на поведение вместо наследяване.

```typescript
@Component({
  selector: 'app-listing-card',
  hostDirectives: [
    Tooltip,
    { directive: Trackable, inputs: ['trackId: analyticsId'], outputs: ['tracked'] },
  ],
  template: `...`,
})
export class ListingCard {}
```

```html
<app-listing-card analyticsId="listing-42" (tracked)="onTracked()" />
```

По подразбиране inputs и outputs на host директивата **не са** част от публичния API на компонента. Те се изнасят изрично в масивите `inputs` и `outputs`, по желание с alias след двоеточие.

Няколко правила, които се питат:

- **Ред на изпълнение.** Host директивите се изпълняват **преди** компонента: конструкторът им, после конструкторът на компонента. Същото важи за `ngOnInit` и за host bindings. Затова host bindings на компонента се прилагат последни и могат да презапишат тези на директивата.
- **DI.** Компонентът може да инжектира своите host директиви, а те могат да инжектират компонента. Ако и двата предоставят един и същ токен, печели компонентът.
- **Статичност.** Host директивите се прилагат при компилация и не могат да се добавят по време на изпълнение. Селекторът на директивата се игнорира. Директивата не може да е със `standalone: false`.

Типичният случай е библиотека от UI компоненти. Поведения като tooltip, фокус, клавиатурна навигация или ARIA атрибути се пишат веднъж като директиви и се комбинират в различни компоненти, без дълга верига от наследяване.

## Pipes

Pipe-ът трансформира стойност в израз на темплейта. Стойността минава през символа `|`, параметрите се подават след `:`, а няколко pipes се изпълняват отляво надясно.

```html
<p>{{ listing.price | currency: 'EUR' }}</p>
<p>{{ listing.publishedAt | date: 'dd.MM.yyyy' }}</p>
<p>{{ listing.title | slice: 0 : 40 | uppercase }}</p>
```

Вградените pipes са в `@angular/common`: `async`, `currency`, `date`, `decimal`, `percent`, `json`, `keyvalue`, `slice`, `lowercase`, `uppercase`, `titlecase`, `i18nPlural` и `i18nSelect`. Форматиращите pipes използват текущия locale на приложението.

### Приоритет на операторите

Pipe-ът има **по-нисък** приоритет от аритметичните и логическите оператори, затова `firstName + lastName | uppercase` първо съединява низовете, после ги превръща в главни букви. Той има обаче **по-висок** приоритет от тернарния оператор. Затова изразът `isAdmin ? 'Достъп' : 'Отказ' | uppercase` прилага pipe-а **само към втория клон**. Когато приоритетът не е очевиден, се използват скоби.

### Pure срещу impure

Това е най-важният въпрос за pipes.

**Pure pipe**, което е поведението по подразбиране, се изпълнява отново **само когато входът се промени**. За примитиви това означава нова стойност, а за обекти и масиви нова **референция**. Резултатът на практика е мемоизиран: при всеки цикъл на change detection Angular сравнява входа и, ако е същият, използва предишния резултат.

Следствието е, че **мутация не се вижда**. Ако в масив, подаден на pure pipe, се добави елемент с `push`, референцията е същата и pipe-ът не се изпълнява отново. Решението е нов масив, тоест същото правило за непроменимост като при OnPush в [[change-detection-onpush]] и при чистите reducers в [[ngrx-architecture]].

**Impure pipe**, с `pure: false`, се изпълнява **при всеки цикъл на change detection**, независимо дали входът се е променил. Той вижда мутациите, но е скъп. Документацията предупреждава, че невнимателната употреба може сериозно да забави приложението, и препоръчва думата `Impure` в името му.

### Защо `async` pipe е impure

`async` pipe е impure, и причината е точно в неговата работа. Входът му, тоест референцията към observable-а, обикновено **не се променя**. Променя се стойността, която observable-ът излъчва. Pure pipe не би се изпълнил отново, защото референцията е същата. `async` pipe трябва да провери при всеки цикъл дали има нова стойност. Той се абонира при първото изпълнение, отписва се при унищожаване на компонента и при нова стойност вика `markForCheck()`, затова работи и в OnPush компоненти. Тази вътрешна работа е от общото знание за Angular, а не от страницата за pipes.

### Собствен pipe

```typescript
@Pipe({ name: 'area' })
export class AreaPipe implements PipeTransform {
  transform(squareMeters: number, unit: 'm2' | 'sqft' = 'm2') {
    return unit === 'm2' ? `${squareMeters} м²` : `${Math.round(squareMeters * 10.764)} sq ft`;
  }
}
```

Pipe-ът се добавя в `imports` на компонента, за да се използва в темплейта му. Името е в camelCase.

Документацията дава и практичен съвет. Логиката на pipe-а не трябва да се използва чрез инжектиране на pipe класа в service. Вместо това тя се изнася в обикновена функция, която използват и pipe-ът, и service-ът. Вградените pipes имат такива функции: `formatDate`, `formatCurrency`, `formatNumber` и `formatPercent`.

### Pipe срещу метод в темплейта

Класически въпрос е защо `{{ getArea(listing) }}` е по-лошо от `{{ listing | area }}`. Методът в темплейта се изпълнява **при всеки цикъл** на change detection, защото Angular не знае дали резултатът е същият. Pure pipe-ът се изпълнява само при нов вход. При signals същата роля има `computed`, който също е мемоизиран и се преизчислява само при промяна на зависимостите си.

## Изречението за интервю

> Компонентът е директива с темплейт. Директивата добавя поведение към съществуващ елемент без собствен темплейт, а pipe-ът трансформира стойност в израза на темплейта. Attribute директивите променят външния вид или поведението на елемента. Структурните променят DOM, а звездичката е захар за `<ng-template>`, затова на един елемент има само една. Директивата рендерира шаблона чрез `TemplateRef` и `ViewContainerRef`. За обикновени условия използвам `@if` и `@for`, а собствена структурна директива само за преизползваема логика, например проверка на роля. `hostDirectives` композира поведение в компонент без наследяване, а host директивите се изпълняват преди компонента. Pure pipe се преизчислява само при нов вход по референция, затова не вижда мутации, а impure pipe се изпълнява при всеки цикъл. `async` pipe е impure, защото референцията на observable-а не се променя, а стойността му да. Pipe е по-добър от метод в темплейта, защото методът се изпълнява при всеки цикъл.
